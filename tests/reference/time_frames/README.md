# 时间与地球定向参考案例

## 旋转矩阵

`erfa_2_0_1_c2t06a.csv` 从 [ERFA v2.0.1 的 t_c2t06a](https://github.com/liberfa/erfa/blob/v2.0.1/src/t_erfa_c.c#L2491) 手工摘录，三行三列，行优先，完整许可证保存在 `ERFA_LICENSE.txt`。

固定输入：TT = UT1 = JD 2400000.5 + 53736.0，xp = 2.55060238e-7 rad，yp = 1.860359247e-6 rad。为了通过本工程 Epoch/EOP 接口表达相同输入，取 TAI = TT − 32.184 s、UT1−TAI = +32.184 s。这是上游合成案例，不是该日的实测 EOP。

每个矩阵元素的绝对容限为 1e-12，与上游参考测试一致。C++ 和 Python 使用同一固定 CSV，测试不会覆盖参考值。此项验证适配层的历元、单位、输入拆分、矩阵方向及 Python 绑定，属于**同源参考回归**，不是独立实现交叉验证或对真实地球定向精度的认证。

补充几何性质检查：`R R^T` 与单位阵每个元素相差不超过 1e-14，行列式与 +1 相差不超过 1e-14；约 9000 km 尺度位置的正逆变换与长度保持容限为 1e-8 m。性质检查独立于 CSV，但不能独立证明所选天文模型的绝对精度。

## 时间

时间数据依据 `data/manifests/iers_leap_seconds_2026_07.json` 指定的 IERS 原文。测试单独列出全部 27 次正闰秒的生效日期，检查各边界前后及最后一个纳秒、偏移值、UTC/TAI 精确往返。整数时间断言要求完全相等。

TAI 零点与 J2000 TT 分别验证，TAI→TT 的时间差容限为 2e-11 s（只比较拆分后的差值，避免相加 JD 的精度损失）。这个容限验证浮点转换，不等同于整条 UTC/TAI/TT 链路的绝对物理时标准确度。

额外错误案例覆盖：非法日历/时钟、非闰秒日期的第 60 秒、纳秒越界、快照两端、极端整数输入、EOP 缺少来源、错误历元、非有限数值和明显超出定义域的 EOP。

后续真实 EOP 数据、dX/dY、完整状态变换落地时，必须补充固定数据版本和独立交叉验证；不能仅增加同一 ERFA 实现生成的 golden 文件就宣称完成这项验证。
