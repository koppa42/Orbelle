# 桌面软件更新

Windows x64 便携版在主窗口打开后异步检查 GitHub Release。有更新时显示非模态提示，提供下载、稍后和跳过此版本；“帮助 → 检查更新”可手动检查并重新发现跳过的版本。“启动时检查更新”默认开启，在“工具 → 首选项 → 软件更新”中设置，与网络代理等全局偏好统一应用；更新提示与帮助菜单不重复放置这个开关。离线、限流和后台检查失败不弹出错误窗口；手动检查会显示失败原因。下载和校验可取消，不阻塞场景编辑。

## 版本与来源

应用版本由 CMake `PROJECT_VERSION` 编入程序。检查固定调用 `koppa42/Orbelle` 的 GitHub Releases latest API，只接受已发布的非预发布版本 `vX.Y.Z`，按三个数字分量比较。文件日期、名称变化和附件数量都不决定是否有新版。ETag 缓存用于条件请求；缓存损坏时重新获取。无需用户令牌，程序不内嵌 GitHub 凭据。

下载地址必须对应同一官方仓库、同一版本、固定附件名称；重定向只接受 GitHub 的 HTTPS 下载域。版本说明以纯文本显示。GitHub HTTPS 和仓库发布权限是本实现的信任边界，SHA-256 用于完整性校验，并不等同独立的发布者签名。

## 分包与复用

每次发布除完整 `Orbelle-X.Y.Z-win-x64.zip` 外，还提供三个更新 ZIP 和一份 `Orbelle-X.Y.Z-win-x64-update.json`：

| 分包 | 内容 | 复用规则 |
| --- | --- | --- |
| `app` | 主程序、原生更新器和启动器、Qt 路径配置、文件清单 | 本地逐文件大小、SHA-256 全部一致时复用 |
| `runtime` | DLL 和 Qt 插件 | 仅依赖变化时下载 |
| `resources` | 地图、着色器、PROJ/GDAL 运行数据和许可证 | 仅资源变化时下载 |

当前按分包下载，不提供二进制差分补丁；一类中有文件变化就下载该类完整 ZIP。清单列出完整新版本的文件、分类、大小和 SHA-256，以及各 ZIP 的大小与 SHA-256。发布端验证整包与分包的内容一致。客户端先核验本地文件，再下载缺少的分包，在独立暂存目录组装完整新版，逐文件核验后才发布为版本目录。复用采用复制，不让两个版本共享可修改的硬链接。

拒绝路径穿越、绝对路径、Windows 设备名、大小写别名、链接、额外 ZIP 条目和不匹配的大小、哈希或 CRC。清单和解包有数量及大小上限；失败或取消只清理本次暂存，活动版本保持不变。

## 安装与清理

便携包根目录包含无 Qt 依赖的原生 `Orbelle.exe`，通过 `active-version.txt` 选择 `versions/X.Y.Z/OrbelleApp.exe`。全部 DLL、插件和资源与主程序放在同一版本目录。根启动器和更新器使用静态 MSVC 运行库，避免依赖应用 DLL 才能修复或切换版本。协议与进程测试见[原生更新交接](../../apps/desktop/updater/README.md)。

下载完成后由用户点击“重启并更新”。工作台先执行原有的忙碌检查、未应用草稿及未保存项目确认，再异步启动新版目录内的更新器。更新器确认持有当前进程句柄后才允许退出；取消或交接失败时仍保留当前窗口。更新器等待正常退出，不强制终止用户程序。

新版进入可用窗口并响应启动握手后才切换活动版本；首次数据准备窗口也可确认程序启动，避免下载大型科学数据时被误判为崩溃。启动失败保持旧版本并重新打开。该检查验证启动，不代表所有计算功能的完整回归。

成功后自动清理旧程序和本次下载缓存，通常只保留一份程序。旧目录必须有有效的管理标记和完整文件清单，所有文件内容一致且没有额外文件、目录、链接或用户数据才允许清理；否则保守保留。文件被占用或清理失败不会破坏可用新版。项目、数据中心下载内容和设置不属于软件更新包。清理完成后如需退回旧版，需要重新下载。

程序安装目录需可写，更新期间仍需容纳新旧程序及必要下载包。数据目录默认在应用本地数据位置，可由 `ORBELLE_DATA_HOME` 指定；软件更新不迁移或删除科学数据。未来数据格式不兼容时需单独设计兼容策略，不能把程序回退当作数据库回退。

## 交付资源与验证

打包使用明确的运行资源白名单，不复制整个构建资源目录。测试 EOP 片段、glTF 测试模型、基准字体及场景、PDB、CMake 和 vcpkg 构建描述不进入完整包或资源更新包。正常启动从用户目录读取数据，并在缺少完整数据时显示初次准备；测试模式通过包外 `ORBELLE_TEST_RESOURCES` 提供固定样例，普通启动忽略该变量。

Qt 回归覆盖异步检查、版本判断、缓存、跳过、取消、分包复用与校验失败；原生子进程回归覆盖交接、启动失败恢复、锁、参数转发及保守清理；打包回归验证资源白名单和完整包／分包一致性。真实便携包另做迁移后的启动及 GPU smoke，界面检查包含不同 DPI。

已经发布的 v0.3.1 不包含更新功能。首次升级到 v0.4.0 需手动下载、解压完整便携包；之后支持上述流程。源码开发构建及缺少更新附件的版本可查看发布页，但不会尝试覆盖开发目录。
