# 地球轨道向导与设计求解

桌面“插入对象 → 卫星 → 轨道向导”、C++ `core::design_earth_orbit` 和 Python `design_earth_orbit` 共用 Core 求解器。设计只产生初始输入，桌面继续进入卫星属性草稿，确认插入后才创建对象；取消不提交。无需联网或载入重力文件。历元继承场景起始时刻，角度以 GCRF 固定赤道面为基准，高度相对 IERS 2003 地球赤道参考半径 6378136.6 m。

类型参考 [STK Orbit Wizard](https://help.agi.com/stk/12.10.0/Content/stk/tools-05.htm) 和 [OrbitWizard 参数定义](https://help.agi.com/stk/12.7.0/SubSystems/connectCmds/Content/cmd_OrbitWizard.htm)，采用自己的参数布局，并不复刻 STK 的全部选项或默认值。

| 类型 | 独立设计条件 | 自动求解 / 传播器 |
| --- | --- | --- |
| 圆轨道 | 高度、倾角 | e=0；二体；倾角 90° 即极轨道 |
| 临界倾角 | 近远地点高度、顺行 / 逆行 | i=acos(±1/√5)，J2 近地点幅角长期变化为零 |
| 临界倾角太阳同步 | 近地点高度 | i=116.565051…°；解 a、e，使升交点进动等于平均太阳运动；J2 |
| 地球同步 | 顺行倾角 <90° | 二体周期等于名义恒星日；i=0 为理想静止轨道 |
| 闪电（Molniya） | 近地点高度、近地点幅角 | i=63.434948…°，反解 a、e，使 J2 近点周期为半恒星日；近地点幅角默认 270°；J2 |
| 自定义 | a、e、i、Ω、ω、ν | 二体闭合椭圆 |
| 重复地面轨迹 | 整数重复圈数 N、交点日数 D、倾角 | e=0，反解 a；J2 |
| 重复太阳同步 | N、D | e=0，联立解 a、i；J2 |
| 太阳同步 | 高度或倾角 | e=0，求另一项；J2 |

所有类型用升交点赤经及初始相位定义定向；圆轨道输入纬度幅角，椭圆输入真近点角与近地点幅角。目前不提供 STK 的地方时、地固升交点经度和星下点经度定向。太阳同步表示节点进动约束，不把 RAAN 数值当作地方时。

桌面采用左侧参数、右侧地图布局，结果摘要置于地图下方，长参数区独立滚动；窄窗口改为整页纵向滚动，底部确认与取消保持可达。地图复用 GroundMap 的离线影像、经纬网、跨经度接缝处理和缩放平移，支持 1 / 3 圈预览。影像通过 Qt 隐式共享复用，不重复解码。拖动时单圈使用约 128–256 段、三圈使用约 256–512 段的预览折线，停止输入 100 ms 后生成每圈 360 段的精细图层；这些采样仅用于显示。旧图层保留到精细图层绘制完成，再用 160 ms 的缓入缓出过渡替换。对预乘颜色逐通道插值，避免重合线段在中途变暗；新参数、无效输入或视口变化会取消旧过渡，不延迟操作。地图底部操作说明保持不变，不在拖动和停止时切换文案或改变布局。相同事件内的修改合并，缓存就绪后直接以最新设计生成有界的预览点集，不再等待另一帧定时器或后台完成通知。EOP 查询、ERFA 定向计算和完整轨迹采样仍在后台运行。尺寸变化只调整现有控件，不重新生成设计。

预览使用同一二体 / J2 Session 以及活动场景的 ERFA / IERS GCRF→ITRF 旋转，按 WGS84 投影。单个后台作业和修订检查防止积压与旧结果覆盖；修改为无效输入时立即清空旧轨迹，但保留结果摘要的行列，以占位符替换无效值。具体校验错误集中在参数区，“继续设置属性”在输入无效时禁用；地图只标记预览暂停，不重复显示参数错误。校验区预留空间，地图状态栏按当前宽度保留所需高度，结果数字不自动折行；宽窄摘要的切换带滞回，连续输入不改变地图尺寸、缩放和平移。后台结果使用标准 C++ future 保存，通过绑定窗口上下文的 Qt 队列通知发布，不依赖可选的 Qt Future 功能，也不轮询等待。销毁预览时先取消并等待作业结束，再由 Qt 丢弃尚未投递的回调。缺少或超出 EOP 覆盖只禁用地图，不阻止有效轨道设计进入草稿；不使用假定格林尼治角替代真实地球定向。

数值输入下方配有双向联动的参数滑条，可用鼠标或方向键粗调，输入框仍接受精确数值和兼容单位。滑条同步不会舍入输入值；高度先采用适合近地设计的范围，直接输入更高数值时自动扩展滑条范围，求解器的有效范围不变。未获得焦点的滑条不响应滚轮，避免滚动长表单时误改参数。

交互定向网格的时长取覆盖预览时段的最小 2 的幂秒数，再均分为 256 段（单圈）或 512 段（三圈）。高度、倾角等参数在同一时长区间变化时，采样时刻仍完全一致，可以复用精确的地球定向矩阵。后台准备网格不因普通参数编辑反复取消；完成后只将它用于当前最新设计，绝不发布旧设计轨迹。切换 Provider 或输入失效时仍取消，完整采样仍严格检查修订。最多保留两份交互网格和一份完整网格（2107 个时刻与矩阵，约 165 KiB），避免来回跨越时长边界时重复准备，也不随拖动次数增长。图层过渡最多额外保留上一幅轨迹图和一幅复用的混合图，尺寸跟随当前地图与 DPI；结束或取消后立即释放，不保留过渡历史。超过当前预览时长的预取遇到数据边界时停止，必要时直接计算精确时长的完整网格，不因预取范围缺数据而拒绝有效预览。

交互阶段每个已采样点都由共享 Session 和精确旋转矩阵生成；仅显示折线的最后一段按请求结束时刻裁剪，并处理跨经度接缝。这是折线显示插值，不生成用于分析或导出的插值状态，也不近似地球定向矩阵。停止后的 361 / 1081 个点包括精确结束时刻，与原模型逐点一致。

## 模型与约束

使用 [J2 长期项模型](j2.md) 的同一组常数和一阶频率。设 n=√(μ/a³)、p=a(1−e²)、q=J2(R/p)²：

- Ω̇=−1.5 nq cos i；
- ω̇=0.75 nq(5 cos²i−1)；
- Ṁ=n[1+0.75 q√(1−e²)(3 cos²i−1)]。

名义地球自转速率为 7.2921150×10⁻⁵ rad/s，平均太阳运动为 2π/(365.2422×86400) rad/s。它们定义初步设计条件，不替代 IERS 随时间变化的地球定向。太阳同步圆轨道由 Ω̇=太阳运动解析求倾角，反解高度时用相同关系。临界倾角太阳同步固定近地点半径 rp，使 e=1−rp/a，再求 Ω̇。闪电轨道使用 Ṁ=2×地球自转速率，临界倾角下 ω̇=0。

重复轨迹条件为 (Ṁ+ω̇)/(地球自转速率−Ω̇)=N/D；交点周期为 2π/(Ṁ+ω̇)，重复周期为 N 倍交点周期。一个交点日是地球相对节点转过一圈的时间，通常不是 86400 s。界面同时给出实际重复周期（24 h 天），避免混淆。N、D 可以有公因数，此时给出指定周期，不声称是最短周期。设计仅针对圆轨道；椭圆仅满足平均节点频率比不足以保证整条地面轨迹闭合。

重复条件的思路参考 [AGI 官方重复地面轨迹说明](https://analyticalgraphics.my.site.com/faqs/articles/Knowledge/What-equations-does-STK-use-to-compute-repeating-ground-tracks)。该文中使用修正后的角速度计算部分进动项；本实现严格使用仓库既有的一阶 J2 约定，不引入隐式 J2² 项。因此不能把结果宣称为 STK 同配置数值复现。

求根采用有界二分，最多 100 次，不扫描长弧、不做数值积分。半长轴上限 106378136.6 m；所有输入需有限、0≤e≤0.99999、近地点高于参考表面，重复计数为 [1, 1000000] 整数；没有包围根的输入明确报错。桌面不截断或静默替换无解条件，只保留草稿并提示调整。

带 J2 约束的输出是平均椭圆的几何根数；`EarthOrbitDesign.secular_j2` 指明语义。桌面将它转换为辅助椭圆 Cartesian 状态并选择 `j2_secular`，不把它当作带短周期项的瞬时状态，也不误用二体传播。设计不包含阻力、短周期、第三体或轨道维持；切换到 HPOP 后应重新评估任务约束。项目文件保存已有 OrbitInput，无格式变更。

## API 示例

```python
import orbelle as ob

request = ob.EarthOrbitDesignRequest()
request.type = ob.EarthOrbitType.REPEATING_SUN_SYNC
request.epoch = ob.Epoch(0)  # 显式 TAI 历元，实际任务使用场景历元
request.repeat_revolutions = 233
request.repeat_days = 16
design = ob.design_earth_orbit(request)
e = design.elements  # 此例为圆形 J2 平均椭圆
session = ob.make_j2_session(ob.J2MeanElements(
    e.epoch, e.semi_major_axis_m, e.eccentricity, e.inclination_rad,
    e.raan_rad, e.argument_of_periapsis_rad, e.true_anomaly_rad), "designed")
# 上面的 M=ν 只适用于圆轨道。一般椭圆应显式进行 ν→M 换算。
```

C++ 包含 `<orbelle/core/propagation/orbit_design.hpp>`；参数单位为 m、rad、连续 TAI 秒。返回值拥有自身数据，失败抛出带错误类别的 `OrbitDesignError`；Python 映射为 `ValueError`。求解不读取全局数据目录，输入不变，适合桌面即时计算与脚本批量设计。

## 验证

- `OrbitDesign.*` 检查解析 GEO、临界倾角、太阳同步双向设计、近地点约束、重复比例、非有限输入、不可达条件和类型错误。
- `tests/reference/propagators/orbit_design.txt` 由 `tools/validation/generate_orbit_design_reference.py` 使用 mpmath 1.3.0 / 60 位精度独立求根生成；临界太阳同步和闪电轨道在偏心率域使用割线法求根，区别于产品的半长轴域二分。检查 a≤1 μm、e≤1e−13、i≤1e−12 rad、Ω̇≤1e−18 rad/s、周期≤1e−8 s；这是同模型的数值对照，非 STK 数据。
- `OrbitDesignPropagation.*` 将实际 J2 Provider 的结果变换到匀速旋转地球坐标，检查 233 圈 / 16 交点日的普通和太阳同步重复轨道，在 −1、1、10 个重复周期后位置闭合误差≤1 mm。
- Python 3.13 检查公开类型、不可达条件与实际传播闭合；Qt 检查 9 类草稿、传播器选择、隐藏的无效输入不污染当前类型、单位、取消和窄布局；真实图形 smoke 保存全部类型及窄窗截图。

尚未执行 STK 实机同配置对照，也未将此初步设计模型与完整 HPOP 长期轨道维持等同。
