# 场景与属性工作流

本轮按已确认的操作顺序实现：**创建 Scenario → 插入对象 → 编辑对象属性 → 播放与检查**。P1/P2 的轨道与 Access 目标继续推进；当前可用的传播器为二体，地面站和 Access 入口尚未实现。

## 桌面操作

1. 启动默认显示场景入口，不自动创建卫星。点击“新建场景”输入名称和分析起止时间。默认 **UTC 当天 00:00:00 至次日 00:00:00**；使用运行时 UTC 日期，不受主机本地时区影响。日期、时间和时间标准合并为一个完整输入框，例如 `2026-10-09 00:00:00 UTC`，可直接输入或粘贴；日历图标展开日期、时分秒和时间标准。弹层中切换 UTC / TAI / TT 保持同一物理时刻，修改文本则按所写的时间标准解释。取消不会创建场景。
2. 新场景只有场景根节点和地球。通过“插入 → 插入卫星”、工具栏或对象树空白处右键打开插入面板。创建场景前此命令不可用。
3. 输入对象 ID、地心 GCRF 初态和初始历元，点击“插入卫星”后才加入场景。初态支持 Cartesian 位置/速度及经典瞬时轨道根数（a、e、i、Ω、ω、ν）。根数界面默认使用 km、度，点击单位可切换并自动换算；公共 API 使用 m、弧度。椭圆、双曲线可转换，抛物线使用 Cartesian；不把 J2/TLE 平均根数当作瞬时根数。可重复插入多颗卫星；重复 ID 被拒绝。对象分析时段继承所属场景。
4. 场景树右键“属性”或双击对象，默认在主工作区标签页中打开属性。二维、三维主视图与属性都是可拖动、可关闭的页面；切换标签保留未应用输入，标签栏右侧按钮可将当前页弹出或放回工作区。场景属性与卫星属性分别保有页面，卫星编辑器一次编辑一个对象。重新从对象树打开对象会装入已应用值；单击其他对象只改变选择，编辑目标仍以标签标题为准。
5. 修改轨道或外观后点击各页的应用按钮生效；关闭面板不会自动提交草稿。异步更新期间仍可播放当前已发布结果；计算取消或输入/资源错误保留原对象。更新期间暂停新建、插入和切换属性目标，避免提交到错误对象。
6. 默认卫星是点标记。已插入卫星可选择内置模型或本地 `.glb/.gltf/.vsgb/.vsgt` 模型，并配置示意显示直径。尺寸按包围盒归一，朝向固定于 ITRF；两者仅用于显示。
7. 拖动二维、三维或属性标签到页面左、右、上、下边缘形成分屏；拖到另一个标签栏合并，在标签栏内拖动调整顺序。拖出主工作区可独立显示，拖动中按 Esc 取消；分隔条可调整各组比例，标签右键也提供分屏、合并和弹出操作。关闭二维或三维页后，通过“视图”菜单或快捷键重新打开；相机、地图缩放与当前时间保持不变，页面移动不触发轨道传播。
8. 二维、三维和对象树共用选择与时间轴。各视图工具栏提供适配、定位所选卫星和缩放，显示设置收进右侧菜单。二维支持星下点、地面轨迹、经纬网、昼夜分界和太阳直射点；滚轮缩放、拖动平移，双击或 Home 复位，指针悬停显示经纬度。点击星下点选择同一卫星，点击空白处取消选择。仅打开二维时播放和时间跳转继续工作。

启动页另提供明确的“打开二体示例”，仅在用户选择后创建场景与一颗示例卫星。当前尚无场景保存功能，替换已有对象的场景会在应用内提示数据丢失并允许取消。现有场景时段在本版本中保持固定，可新建不同时间范围的场景。

| 快捷键 | 操作 |
| --- | --- |

| Ctrl+Shift+S | 插入卫星 |

## 统一交互约定

- 炭灰底板、低饱和蓝灰强调、细边框、紧凑布局、统一字体和自绘矢量图标；日期/时间采用整块输入与按需弹出的选择面板。
- 对象树单击负责选择，双击负责属性，右键提供上下文操作。所有入口复用同一命令。
- 默认单一主视图，辅助视图按需打开。时间轴属于场景，默认仅显示场景分析区间；“时间 → 显示所选卫星区间”可按需展开一行卫星传播区间，不给每颗卫星常驻一行。
- 属性左侧为可折叠分组树：“基本 → 轨道、轨迹范围”“二维视图 → 显示”“三维视图 → 显示与模型”。插入卫星前仅开放轨道页。参数按“传播设置”和“初始状态”分两栏，数值与可点击的单位选择器组成完整输入框，统一移除上下按钮，保留键盘微调和校验。页面保留字段、单位、必要状态及错误；补充说明放在相关控件的悬停提示，自定义时长仅在选择自定义范围后显示。
- 按用户反馈删除时长快捷设置、±1分钟、零点及重复日期快捷项。完整时间框支持最多9位小数秒、有效 UTC 闰秒 `23:59:60`；弹层的时、分、秒输入保留上下调节按钮，单击分别增减1小时、1分钟、1秒，长按连续调节，也可直接输入毫秒。只打开、切换时间标准及确认不会丢失原始纳秒。直接粘贴的 TAI / TT 标准在重新绑定时保留；TAI/TT 不接受闰秒60。Escape 或点击弹层外取消草稿，确定后才更新完整输入框。默认一天按 UTC 日历次日计算，闰秒日可为86401秒。
- 创建按钮为新建场景面板的默认动作。卫星属性内容最小宽910逻辑像素，分屏后空间不足时滚动；轨道双栏表单最大宽800，数值与单位组合框最大宽276，历元框最大宽380逻辑像素，随显示缩放适配。大窗口将余量留在表单右侧，单位紧跟数值；场景名称、轨迹范围及模型参数也设置宽度上限。弹出与放回使用同一份输入控件，不重建草稿。关闭属性仅关闭该页面。
- 参考 STK 的场景先行、对象浏览器、分类属性页、全局时间控制，不复制其图标或资源。[STK 场景教程](https://help.agi.com/stk/12.10.0/Content/training/L1_BuildScenarios.htm)、[对象浏览器](https://help.agi.com/stk/Content/gettingstarted/GetStart_ObjectBrowser.htm)、[对象属性](https://help.agi.com/stk/content/stk/ObjectProperties.htm)、[时间轴](https://help.agi.com/stk/content/gettingstarted/GetStart_7_TimelineView.htm)。

### 带单位的数值输入

桌面组件 `QuantityEditor` 位于 `apps/desktop/src/viewer/quantity_editor.hpp`。点击框内右侧单位，只列出同一物理量的可选单位；选择后换算左侧数值，保持物理量不变。读取时显式指定目标单位，不依赖当前显示单位，也不需要调用者再乘换算系数。

| 物理量 | 可选单位 | 使用位置 |
| --- | --- | --- |
| 角度 | °、rad | 倾角、升交点赤经、近地点幅角、真近点角 |
| 长度 | m、km | 位置、半长轴、模型示意直径 |
| 速度 | m/s、km/s | Cartesian 速度 |
| 时长 | ms、s、min、h、d | 显示步长、轨迹前后时长 |
| 引力参数 | m³/s²、km³/s² | μ |

```cpp
using orbitforge::desktop::QuantityEditor;
using orbitforge::desktop::Unit;

QuantityEditor angle(Unit::degree);
angle.set_value(180, Unit::degree);
angle.set_unit(Unit::radian);             // 显示约 3.14159265358979 rad
const double radians = angle.value(Unit::radian);
const double degrees = angle.value(Unit::degree); // 180，与显示单位无关
```

组件以 SI 值保存未编辑的物理量；显示采用15位有效数字，反复切换单位不会把显示舍入写回存储。文本输入使用小数点并支持科学计数法。无效或未完成的输入保留原文并标记错误，读取及换单位会拒绝该输入；不同物理量之间的单位转换同样被拒绝。偏心率无量纲，不显示单位菜单。

`set_range(min, max, unit)`、`set_single_step(step, unit)` 和 `set_quantum(quantum, unit)` 都按明确单位定义物理约束。显示步长继续限定为1–60整数秒，例如 `0.75 min` 等于45秒，`0.751 min` 被拒绝。键盘上下键的物理增量不随显示单位改变。这里的 `d` 是86400秒时长，不用于替代 UTC 日历的“次日”。

`valueChanged` 只报告有效物理值的变化，参数是 SI 值；纯单位切换只触发 `unitChanged`。重新绑定参数时保留当前控件的单位选择；此选择目前不跨程序重启保存。单位切换不自动传播轨道，仍由应用按钮提交。公共计算 API 与 Python 保持原有 SI 约定，桌面适配器按明确单位读取；现有显示设置中分钟和千米字段的存储格式保持不变。

## 公共 API 与发布边界

`Application::Scenario(name, first, last)` 初始没有对象，要求非空名称和正向时间区间。`with_object(session)` 返回新场景值；新 ID 从修订 1 开始，替换只接受该 ID 的下一修订，旧版本继续可读。`sample(epochs)` 先检查所有历元均在场景区间内，再调用各 Session。Python 暴露同一实现，没有 Qt 依赖。

桌面先在后台准备候选 Session 及当前显示范围的 GCRF、ITRF Hermite 缓存，再通过 GPU 编译屏障安装轨迹；成功后同时发布场景修订和对象。每个卫星各有轨迹、模型宿主与显示设置。后续移动显示缓存不会递增 Session 或场景修订。显示缓存不作为后续 Access 分析的数据源。

Python 示例见 `examples/python/two_body_scenario.py`。场景目前是内存中的不可变对象集合；不声称已实现完整项目文件、撤销/重做或所有 STK 对象。

### 坐标系与按需显示缓存

三维默认使用地心 **GCRF**，惯性轨迹保持在该坐标系中，地球随场景时刻按 ERFA/IERS 的 GCRF↔ITRF 旋转更新。视图工具栏可切换 ITRF，保持同一时刻和观察方位；相机、轨迹、点标记、模型及 WGS84 遮挡拾取使用一致的坐标转换。二维始终使用 ITRF/WGS84，不随三维坐标选项改变。

显示步长默认 **60 s**，可设1–60 s。默认显示“一圈轨迹”，按二体初态求周期，围绕当前时刻并限制在场景内；边界处平移范围以保留完整一圈，非闭合轨道改用一小时。首次只准备此范围及15%前后缓冲，不预计算整天。跳转到未缓存时刻时，当前位置立即由 Session 求值，轨迹在后台补齐；过期请求的结果不发布。播放继续使用已发布数据，失败保留旧缓存并给出状态提示。

“基本 → 轨迹范围”可选择一圈、整个场景时段或自定义前后时长；二维地面轨迹/名称、三维空间轨迹/模型分别设置。已有缓存覆盖所需范围时，仅调整绘制区间；超出时才按需计算。两个视图都隐藏对象轨迹时停止请求新的轨迹缓存。显式选择全时段才准备全时段；之后缩小显示范围可继续复用已有数据。每次缓存最多10001个节点，该限制作用于请求的显示区间。

节点保留完整位置和速度变换，供 Hermite 插值；每段1/4、1/2、3/4位置分别对照直接传播值，GCRF、ITRF抽样误差都必须≤1 m，否则要求减小步长。检查点只求位置旋转，省去不需要的旋转导数。此限值是显示位置插值的抽样检查，既不是轨道物理精度保证，也不代表60 s折线弦段处处误差≤1 m。

### 二维地图的显示约定

二维复用已经发布的 ITRF 状态及轨迹采样，使用 Rocky 的 WGS84 椭球坐标转换得到大地经纬度，按等距圆柱投影显示。它是参考椭球上的显示投影，不包含独立的 ITRF/WGS84 框架实现或新的轨道计算。经度跨越 ±180° 时分割折线，保留沿日期变更线的纬度变化。轨迹候选在三维 GPU 编译与场景提交前准备，成功后一起发布；二维轨迹不作为 Access 分析输入。当前不含二维覆盖区域或其他地图投影。经纬网、轨迹、对象名称与太阳直射点可分别开关。经纬刻度随地图缩放调整；夜侧采用保留海陆纹理的冷蓝乘色与窄边界抗锯齿，避免半透明灰块盖住极区。

二维和三维共用地固太阳方向与场景时刻：ERFA `epv00` 给出日心地球位置，取反归一后以既有 ERFA/IERS 旋转转换到 ITRF。该近似以 TT 代替 TDB，并省略光行时、光行差，仅用于显示光照，限1900–2100年；实际场景仍受所带 EOP/UTC 数据覆盖限制。二维显示的是参考椭球法线与太阳方向决定的几何昼夜边界；抗锯齿不是大气曙暮光或地影分析。太阳直射点使用平行太阳光的法线方向大地经纬度。

三维使用 Rocky 的方向光与大气边缘，夜侧保留弱环境光。关闭“昼夜光照”会同时关闭二维遮罩及三维昼夜/大气显示，并保留模型的环境照明。两视图的明暗曲线适合各自的地图和三维观察用途，不要求像素亮度相同。以上显示效果不作为 Access、日照时长或食区判定依据；未新增物理地影分析。冻结万星基准继续使用原有无贴图、无光照场景。

视图组织参考 [STK 二维图形属性](https://help.agi.com/stk/content/stk/2Dgfxproperties.htm)、[地图交互](https://help.agi.com/stk/content/stk/map.htm)及[三维工具栏](https://help.agi.com/stk/content/vo/votoolbar.htm)。不复制其图标或地图资源。

### 时间轴的浏览与定位

时间轴由紧凑播放控制、全场景总览、详细日历刻度和区间行组成。上方总览始终显示场景完整起止日期，蓝色窗口表示下方的可视范围；琥珀色游标在两层同步标记当前时刻。跨日时显示两端日期，多日刻度补充日期。场景只有一个仿真时刻，卫星、二维和三维共用它。

右侧折叠按钮或 Ctrl+J 可收起总览、刻度和区间行，为视图及属性腾出空间；播放、倍率、精确时间输入仍可操作。展开后保留原来的仿真时刻和浏览范围。工作台使用统一的石墨灰面板、冷蓝选中态和线性图标，常用场景命令集中在左上方；视图工具条与工作区标题对齐，属性页合并标题和对象信息，减少重复留白。

- 单击或拖动下方刻度/区间：跳转到对应时刻并暂停播放。定位使用连续 TAI 毫秒，不经原归一化滑块的10000档量化；完整时间输入继续保留更高精度。
- 拖动总览窗口：浏览时间范围；拖动窗口两端：调整可视区间。双击总览或点击“显示全时段”复位。
- 滚轮：以鼠标位置缩放；Shift+拖动或中键拖动：平移；Shift+滚轮：平移。浏览和缩放不改变仿真时刻，也不暂停播放。
- “定位当前时间”将可视窗口移到游标；手动浏览后，播放不会强行改变窗口。游标在范围外时显示方向提示，仍可在总览看到位置。
- 点击右侧当前时间或 Ctrl+T 打开完整时间输入；UTC / TAI / TT 切换只改变表示，不改变物理时刻或可视区间。
- 焦点在时间轴内时，左右键按当前可视跨度微调（最小1毫秒），Home/End 到场景端点，Page Up/Down 平移，+/− 缩放，F 全时段，C 定位游标。

默认收起卫星行，因为当前卫星都继承场景传播时段，重复常驻显示没有额外信息。打开可选行后，仅显示所选对象的真实传播区间；它不引入独立播放时钟，也不表示已经实现 Access 或任务事件。后续独立有效期、Access 窗口及任务事件可按需加入区间行。

可视跨度最小1秒；不足1秒的场景保留自身跨度。日历刻度逐点经过时间服务转换，UTC 闰秒不按固定 TAI−UTC 偏移近似，细刻度能显示 `23:59:60`。指针定位分辨率为毫秒，物理场景边界仍按原始 Epoch 检查。

### 当前日期的数据覆盖

附带 IERS Bulletin A `finals2000A` 快照覆盖 **2026-09-01 00:00 至 2026-11-01 00:00 UTC**，为当前场景提供极移、UT1 和天极偏移，包含明确标记的预测值。历史二体示例仍使用独立的2000年C04验证快照，冻结万星基准不换数据。数据过期不会静默外推，也不会把今天改成历史日期；创建面板会要求选择覆盖范围内的时段。自动在线更新入口尚未实现。

快照保存原始定宽记录、源文件和子集 SHA-256、来源 URL。Bulletin A 的 dX/dY 原始单位为毫角秒；导入后统一为弧度。五个分量在连续 TAI 上使用相邻割线确定导数的 Hermite 插值，其版本与使用观测率的 C04 插值分开。来源记录中的预测掩码包含插值及导数所依赖的相邻样本，位1=极移、位2=UT1、位4=天极偏移。这些预测不能视作最终 C04 观测值。[IERS 数据源](https://datacenter.iers.org/data/9/finals2000A.all)、[USNO 列定义](https://maia.usno.navy.mil/ser7/readme.finals2000A)。

## 交互与绘制开销

暂停且输入未变化时，复用卫星状态、标记缓冲和时间控件；轨迹传播仍由后台任务按显示范围准备。二维分别缓存底图和轨迹，鼠标悬停只刷新坐标栏。底图缓存覆盖视口及96逻辑像素边距，轨迹精细缓存保留160像素边距；平移时复用图像，经纬刻度和卫星标记独立绘制。昼夜蒙版只有曙暮光边缘执行渐变计算，其余区域直接使用相同的日侧或夜侧常量颜色。

超过1024个路径顶点的轨迹，预览与精细栅格化均在后台完成。先从全部显示路径生成固定2048×1024的全图预览，再生成当前视口、当前设备像素比的精细图像。缩放时优先变换覆盖完整视口且倍率相近的精细缓存，否则使用全图预览；预览可能暂时变软，停止操作后由当前倍率的精细结果替换。首次生成或轨迹内容改变后，预览也要等待后台准备；选择变化只重画精细样式，仍复用相同几何的预览。没有抽稀轨迹顶点、更改传播步长或把预览图像用于分析计算。

每张地图最多一个绘图任务。视口、DPI或内容改变后取消不再适用的精细任务，在轨迹内部每256个顶点检查取消状态；全图预览仅在几何或显示范围改变时失效。精细结果发布同时检查内容修订、完整性、倍率和覆盖范围，过期或部分绘图不能覆盖当前图像。密集轨迹的图像分配和线段绘制均在工作线程完成，任务只接收不可变路径和独立取消标志，不读取 QWidget。

新增、编辑或补充一颗卫星的轨迹，只更新对应的二维轨迹并编译对应的三维静态子图，不重建其他对象、渲染任务或交换链。同类图层共享仍在使用的 Vulkan 管线；所有图层关闭后不由全局缓存持有 GPU 对象。替换旧资源前保留 GPU 同步屏障，窗口重建继续使用原来的完整生命周期流程。

`tools/validation/run_workbench_profile.py` 使用正常工作台、全天60秒采样轨迹及合成 Qt 输入，分别记录三维拖动/缩放、二维悬停/平移/缩放、播放和并排播放的 GUI CPU 耗时与帧间隔。缩放后增加静置阶段，断言精细缓存恢复并保存截图。它不等同于屏幕呈现时间或实际设备输入延迟；正确性另外使用 `run_graphics_smoke.py` 和 Vulkan 同步验证检查。测量结果写入 `out/validation/`，不提交生成报告。

## Windows 便携包

```powershell
python tools/packaging/package_windows.py --build-dir out/build/desktop-graphics --dependency-prefix out/dependencies/installed/x64-windows --output out/releases/OrbitForge-0.1.0-preview-win-x64 --reports out/validation/package-new-run --verify --zip
```

输出目录必须是新目录。整个 ZIP 解压后双击 `OrbitForge.exe`，保留同目录 DLL、`plugins` 和 `resources`。桌面启动不需要 Python 或 Qt SDK，需要支持 Vulkan 的显卡驱动。

验证包括依赖递归解析、文件 SHA-256、ZIP 完整性、删除开发环境搜索路径后的异地目录启动、无参数打开/关闭，以及便携版本完整场景交互检查。这是同一 Windows 主机上的部署验证，不等同于全新虚拟机或所有显卡的兼容性认证。
