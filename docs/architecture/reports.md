# 报告与曲线

第一阶段实现于 2026-10-11。参考 STK 的模板、数据提供器与对象绑定方式，报告计算使用 OrbitForge 的 Runtime。桌面和 Python 共用同一个生成、格式化和 CSV 导出实现。

## 使用

打开场景后选择“分析 → 报告”。左侧依次设置对象范围、报告类型、时间与采样、显示格式；右侧切换表格与曲线。顶部可收起设置，扩大结果区域。报告使用现有工作区标签，可分屏或弹出。

对象右键菜单打开报告时只绑定右击的对象，并在左侧持续显示对象名称和范围。切换内置报告类型保持对象绑定；不适用的类型不可选。对象增加不会扩大绑定范围，对象删除后生成报错。通过“更改…”明确选择全场景或多个对象；加载已经保存的配置会恢复该配置自己的对象范围。

右侧工具栏提供刷新（F5）与当前视图的 CSV/PNG 导出；复制和来源信息位于结果菜单。来源在单独详情窗口查看，不占用结果面积。窄分屏通过“编辑设置 / 查看结果”切换，生成成功后显示结果；宽屏同时展示设置和结果，生成操作固定在左侧底部。“模板 → 另存为模板…”复制当前绑定和设置并创建独立 ID；内置模板保持不变。结果表支持多选行、右键复制或 Ctrl+C，复制内容带列标题。屏幕数值用 12 位有效数字便于阅读，悬停、复制和 CSV 保留完整精度；屏幕时间省略无意义的尾随零。

| 模板 | 输出 |
| --- | --- |
| 场景摘要 | 名称、起止时间、时间系统、对象数量、中心天体 |
| 对象摘要 | 稳定 ID、显示名称、类型、传播/固定站模型 |
| 位置与速度 | 对象、历元、GCRF/ITRF、XYZ、Vxyz |
| 地面站坐标 | WGS84 经度、大地纬度、椭球高、ITRF XYZ |
| 经典轨道根数 | 卫星采样状态的 a、e、i、RAAN、近地点幅角、真近点角；固定 GCRF |
| 经纬高 | 卫星/地面站的经度、大地纬度、WGS84 椭球高；固定 ITRF |
| 轨道距离与速率 | 卫星的地心距离、总速率、径向/横向速率、航迹倾角；固定 GCRF |

“整个场景”包含以后插入的适用对象；“更改…”中取消所有对象选项后可绑定具体对象 ID。重命名不改变绑定，删除对象后保留配置并在生成时报告缺失，避免无提示地产生不完整报告。

所有时间序列报告可跟随场景范围或使用场景以内的自定义区间。步长是整数纳秒，包含起点和终点；不整除时额外保留精确终点，最后一段较短。允许单时刻查询。每个对象的行连续排列，顺序采用项目的卫星、地面站顺序。

报告类型旁的“模板”菜单提供保存、更新和删除；选择“保存为模板…”时才输入名称。保存把定义加入当前项目并标记未保存；再保存项目后写入磁盘。项目 v7 保留配置，不保存数据表。旧 v1–v6 项目可直接打开。取消生成或生成失败保留上次结果；切换配置也不会默默替换已有结果。结果页显示所对应的报告名称，场景输入改变后提示重新生成。双击含历元的行可定位场景时间。

## 曲线与模板操作

左侧固定主操作只有“生成报告”；对象、类型、采样与单位按顺序排列。报告类型旁的模板菜单保存当前选择，使用已保存模板时可原地更新或另存新模板。取消命名不改变项目。模板属于当前项目，保存项目才写入磁盘；界面不再常驻“配置名称”输入框和底部保存按钮。

右侧在“表格 / 曲线”间切换。时间序列报告可选择一个数值字段、对比最多 12 个对象或单独查看对象。超过 12 个时明确使用对象选择器，完整数据仍保留在表格和 CSV。图例最多两行，其余对象可通过选择器和悬停识别。静态摘要不显示时间曲线。视图、字段、对象选择和缩放复用同一不可变结果，不触发传播；修改左侧采样或显示单位仍须重新生成。

曲线支持滚轮缩放、拖动框选时段、右键/Home 还原、方向键平移及双击附近采样点定位场景时间；悬停显示原始样本的精确时间和值。横轴以报告起点为零，自动使用秒、分钟或小时，明确标示起点及 UTC/TAI/TT。经度与周期性轨道角跨越半周时断线。绘图按横向像素保留首尾及极值点，避免降采样抹去单点尖峰；这只影响绘图，不改变表格。连线是离散样本的视觉连接，不是新增计算值。

图表页导出 PNG（2 倍分辨率）或从结果菜单复制图片；表格页导出 CSV、复制选中行。图片包含字段、单位、图例和时间起点，采用当前缩放范围；文件选择器负责覆盖确认，PNG 通过 QSaveFile 原子替换。图形的视图状态和 PNG 不写入项目，当前模板保存的是查询定义。

## 计算与数据一致性

Application 提供 `ReportDefinition`，Results 提供 `Table`（列 ID、名称、基础单位和有类型单元格），Runtime 提供 `ReportContext`、`generate_report` 和 `export_report_csv`。报告直接由输入重建所选对象的 Session 并采样，不读取显示轨迹 `StateTrack`，显示步长与地图插值不影响结果。卫星和地面站的跨参考系计算使用完整状态变换，包含地球旋转引起的速度。

桌面每次生成前检查当前数据是否覆盖完整场景，以及数据身份/外推策略是否与已确认场景一致。变化时沿用场景的数据确认流程：取消则不生成；同意后先重建场景，成功后自动继续报告。一次报告捕获项目、时间/EOP Provider 的共享不可变版本，下载或后续场景编辑不改变运行中的输入。覆盖不足或 UTC 过期不会静默外推；有限 EOP 外推仍由数据中心控制。

结果记录输入 SHA-256、场景数据锁、UTC 数据 SHA-256 和 `builtin-reports-v2` 算法标识。输入哈希使用规范项目编码，排除报告配置、播放时间、显示步长和纯图形设置，保留物理输入、对象名称和数据身份。该哈希用于识别变化，不是结果缓存键或来源签名。

后台任务每批最多 512 个样本，支持进度与取消；桌面表格按需格式化。第一阶段单次最多 **200000 行**，生成前检查上限；超限应增大步长、缩短区间或减少对象。结果仍驻留内存，尚未实现磁盘分页和无限量导出。

根数调用现有 CSPICE 状态转根数实现；J2 输出是采样状态换算的瞬时根数，不是模型输入的平均根数。圆/赤道轨道采用 Provider 的奇异角约定，抛物线或数值病态情况明确报错，不伪造数值。经纬高使用 ERFA `eraGc2gd` 的 WGS84 转换，卫星先通过已确认 EOP 转到 ITRF；椭球高不是离地高度。速率中径向向外为正，横向速率非负，航迹倾角为 `atan2(径向速率, 横向速率)`。

## 单位与 CSV

内部数值始终使用 m、m/s、rad 和 TAI 整数纳秒；工程格式使用 km、km/s、度。UTC 文本保留闰秒，TAI/TT 不带 UTC 的 `Z` 标记，列头明确时间系统。数值格式化采用经典区域设置与 17 位有效数字；时间保留 9 位小数。

CSV 使用 UTF-8 BOM、逗号分隔、双引号转义和 CRLF 行结束符，支持中文、逗号、引号和名称内换行。先写入同目录临时文件，成功后原子发布；默认不覆盖，桌面覆盖须通过文件选择器确认。取消/发布前失败保留旧文件。CSV 只包含表格，不插入哈希前言；本次溯源信息可在来源窗口和 Python 结果对象中读取，暂不自动导出元数据附属文件。

## Python

```python
from pathlib import Path
import orbitforge as of

project = of.Project("Mission", of.Epoch(0), of.Epoch(120_000_000_000))
orbit = of.OrbitInput()
project.add_satellite(orbit)

report = of.ReportDefinition()
report.id = "satellite-state"
report.name = "轨道位置"
report.kind = of.ReportKind.CARTESIAN_STATE
report.frame = of.FrameId.GCRF
report.step_nanoseconds = 30_000_000_000
report.time_scale = of.ReportTimeScale.UTC

print(of.estimate_report_rows(project, report))
result = of.generate_report(project, report)
# 原始数值为 SI；输出格式由 report.units 控制。
print(result.table.columns[4].unit, result.table.rows[0][4])
result.export_csv(Path("state.csv"))
project.reports = [report]
project.save("mission.orbitforge")
```

ITRF/GCRF 转换须显式提供 `eop_manifest`，并将对应 `data_info` 绑定到 `project.earth_orientation`；如果项目使用外部 UTC 文件，传入匹配的 `time_file`。运行时拒绝与项目记录不一致的数据，不自动联网或代替用户确认。默认使用内置 UTC 数据。输入在释放 Python GIL 前复制，生成和导出期间释放 GIL；Python 结果暴露只读数据及配置副本。`Project.reports` 与其他项目列表一样，修改列表后须整体赋回。

STK 的报告内容允许选择数据提供器、重排字段、划分具有不同时间依赖的节，并分别设置单位和统计。对应到 OrbitForge，下一阶段应把“查询字段/区间”和“显示样式”分离；时间序列与 Access 区间需要不同结果结构，避免把区间强行展开成采样行。[内容与统计](https://help.agi.com/stk/Content/stk/report-06.htm)

STK 在结果窗口提供刷新、复制、查找、单位及导出设置。本轮先补齐对象入口、配置副本与表格复制，后续优先完善结果内的格式调整。仍使用简单默认 CSV，需要排版的报告另走文档导出。[结果操作](https://help.agi.com/stk/Content/stk/report_export.htm)

### 界面调整采用的取舍

2026-10-11 再次核对 STK 2026 R1 官方界面操作文档。STK 的报告管理器把对象类型/对象列表、Styles、Time Properties 和 Generate 分区组织，先选对象再选适用样式；报告生成后在结果窗口提供操作工具栏。它不是左侧设置、右侧实时结果的布局。[管理器与对象范围](https://help.agi.com/stk/Content/stk/report.htm)、[官方界面教程](https://help.agi.com/stk/content/training/L1_AccessReports.htm)

OrbitForge 采用用户选择的左右布局，借用其对象优先、适用类型筛选、结果工具栏三个特点。七种报告用紧凑选择器呈现，保存的配置带独立标识；当前数量无需长期占用一列样式树。时间默认使用场景时段，只有选择自定义时段才展开两个时间输入框。配置管理与来源详情保留明确入口，不占用主结果区域。
