# 统一数据中心开发方案

此文记录 2026-10-10 确认的开发方向。已完成的是 [Scenario 数据锁](scenario_data_lock.md)及本地 EOP 导入基础；SQLite 统一目录、在线下载和自动更新尚未实现。

## 管理边界

应用级“数据中心”统一管理数据源、已安装版本、下载任务和更新策略；每个 Scenario 只保存确定版本的引用清单与哈希。第一批覆盖 EOP，随后接入可按实例加载的 UTC 时间数据、SPICE，最后扩展 GP/OMM/TLE。普通用户选择数据类型和来源后即可下载，清单由适配器生成。

数据更新只新增不可变快照。新场景使用已设置的默认版本；已有场景继续使用自己的数据锁，用户显式选择“更新场景数据”后才验证覆盖范围、重建并切换。下载新版本和应用到场景是两个独立动作。

## 存储与引用

计划的应用数据目录：

```text
data/
  catalog.sqlite       数据源、快照、依赖、文件索引、下载任务和策略
  blobs/sha256/...      原始文件，按内容哈希寻址、去重
  snapshots/...        固定快照的解释配置及来源记录
  derived/...          可重建的解析索引或派生产物
  staging/...          尚未校验发布的临时下载
```

SQLite 管理可查询状态；不可变文件和快照描述保留足够信息用于审计与目录重建。数据库行号和本机绝对路径不写入 Scenario。Scenario 通过快照 ID、内容 SHA-256、解释配置 SHA-256 解析实际文件。

多个场景共用相同文件，不各自复制数据。已有 `%LOCALAPPDATA%/OrbitForge/eop` 目录按原身份导入新目录，迁移不能改变既有项目的数据锁。第一版保留已安装快照，不自动删除历史版本；可先清理已结束任务的临时文件和可重建缓存。跨电脑项目可能未登记在本机目录中，不能简单把“当前无引用”当作可永久删除的证据。

## 手动与自动更新

| 策略 | 行为 |
| --- | --- |
| 手动 | 用户点击检查、下载指定版本或导入本地原文件 |
| 自动检查 | 按数据源间隔检查，提示可用版本，等待手动下载 |
| 自动下载 | 自动检查并安装新版本，保持已有场景绑定 |

第一版调度只在应用运行时执行，记录上次检查与下次时间，不增加系统常驻服务。按来源限制并发，提供进度、取消、失败原因和重试。URL、产品类型、覆盖范围、获取时间、源文件哈希及派生关系保留在元数据中；观测值与预测值仍清楚标记。

下载先进入 staging。完成后校验传输结果、文件格式、时间覆盖、数据数值及依赖关系，再计算哈希、发布不可变文件和数据库记录。失败、取消和程序中断不能产生“已安装”的半成品，也不改变正在运行的场景。时间数据更新必须加载并验证新的原文及规则，不能只延长旧表有效期。

## 缺失数据

打开项目时，resolver 检查数据锁并列出缺失依赖。允许根据用户策略下载原版本；下载后必须匹配项目记录的内容和配置哈希。如果上游只保留最新文件，不能用它替代旧引用，应明确提示需要导入原快照，或让用户显式更新场景数据。已安装完整依赖的项目可离线打开。

后续可增加“导出项目及依赖包”，携带 `.orbitforge` 文件、固定清单和所需文件。它复用相同数据锁，属于可移植性功能，不改变统一数据目录的默认工作方式。

## 开发顺序

1. **已完成：** 数据引用值、规范哈希、Scenario 绑定、项目 v3 持久化、旧文件升级和一致性验证。
2. **下一步：** SQLite 目录、文件存储与通用 resolver；统一数据中心窗口；迁移已有 EOP 导入入口；验证两场景共享文件且独立固定版本。
3. EOP 来源适配器与手动下载；直接从原文件创建快照；验证失败、取消、并发导入及断网恢复。
4. 应用运行期间的自动检查/下载策略，缺失依赖下载；实现动态时间 Provider 并让 EOP 依赖明确的时间实例。
5. SPICE 和轨道目录适配器、项目依赖包、容量与历史版本管理。

各增量都保留离线使用能力。验收重点是身份可核验、场景可复现、更新可取消，以及任何下载或应用失败都保留已有可用版本。
