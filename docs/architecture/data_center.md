# 统一数据中心开发方案

此文记录 2026-10-10 的首版实现及后续方向。已完成 [Scenario 数据锁](scenario_data_lock.md)、SQLite 统一目录、左列表、右详情的数据管理窗口及有限 EOP 外推、IERS finals2000A 全量下载和应用运行期间的自动更新。UTC 时间数据仍为内置只读版本，SPICE、GP/OMM/TLE 尚未接入。

## 管理边界

应用级“数据中心”按数据类型管理当前文件、获取时间、覆盖范围和更新操作。左侧采用两级目录：“地球定向参数”为一级，finals2000A 与 C04 是它的二级来源；“UTC / 闰秒”为另一一级条目。底层 `DataInventoryItem` 仍分别表示两种 EOP 来源与 UTC，保留各自的安装状态、获取记录、覆盖范围、文件信息和操作能力；分类与来源身份独立于 Provider 下标。第一批覆盖 EOP，随后接入可按实例加载的 UTC 时间数据、SPICE，最后扩展 GP/OMM/TLE。普通用户不管理历史版本或默认版本，清单由适配器生成。

安装状态区分未下载、内置示例、本地文件、完整包已下载、程序内置。安装、时间覆盖和联网更新结果彼此独立：内置 EOP 示例不算完整包，能覆盖今天不代表联网确认过最新版，历史 EOP 的覆盖结束也不表示文件失效。UTC 的有效截止保留明确的排他边界。

新建场景使用当前数据。打开或重新计算时先检查上次数据身份：相同则继续，不同则说明变化并请求用户确认；允许后使用当前数据重建，取消则不打开或重算，原场景及结果保持不变。默认计算顺序是 finals2000A → C04，可选中“地球定向参数”父级，在右侧拖动来源改为 C04 → finals2000A。先按顺序寻找实际覆盖完整时段的来源，全部不足时才按相同顺序尝试允许的有限外推；优先来源缺失时使用另一来源。两份文件不拼接成一个覆盖区间。

优先级是应用级设置，以 `eop-preferred-product` 存入 SQLite settings，重启、下载与导入均保留；缺失或无效值回退到 finals2000A 优先。修改顺序不替换活动计算中的 Provider，下一次打开或重算时重新选择；仅在实际使用的数据或外推策略变化时请求确认。优先级本身不写入 Scenario 数据哈希，项目仍记录本次计算实际使用的来源，且不要求本机保留旧文件。

一次计算及其显示缓存共用捕获的不可变 Provider；确认弹窗期间完成的下载也不会替换已展示给用户的数据。下载完成不改变已显示结果。用户允许更换数据后，一起重建全部显示轨迹并整体发布，失败或取消保留原场景。普通场景没有历史版本、回滚或手动应用数据的入口。

## 存储与引用

桌面使用 Qt `AppLocalDataLocation/data`，Windows 默认 `%LOCALAPPDATA%/OrbitForge/data`，可通过 `ORBITFORGE_DATA_HOME` 指定其他目录。指定目录后不自动搬迁旧目录；导入时仍保留原数据身份。C++/Python 可显式选择目录：

```text
data/
  catalog.sqlite       文件索引、依赖、获取记录、当前文件指针和更新状态
  blobs/sha256/...      原始文件，按内容哈希寻址、去重
  snapshots/<lock>/    manifest.json、record.json 及数据文件视图
  staging/...          尚未校验发布的临时下载
```

SQLite schema 2 在 `snapshots`、`dependencies`、`settings` 之外增加 `acquisitions`，保存获取方式与 Unix 秒时间。schema 1 升级不编造获取日期，旧数据显示“未记录”。内置数据标记“随程序附带”，没有用户下载时间。只有成功下载或手动导入才记录新的获取时间；304、取消和失败不修改它。获取记录独立于内容哈希与 Scenario 数据身份。

快照目录按依赖清单总哈希命名；record.json 保存清单原始字节的 SHA-256 与依赖身份。数据视图优先使用指向内容文件的硬链接，不支持硬链接时使用经校验的副本。finals2000A 保存整个原文件，不按场景截取；快照内容哈希和来源哈希均为完整原文件的 SHA-256。数据库行号和本机绝对路径不写入 Scenario。每种 EOP 产品保存一个内部当前文件指针，因此同一秒内重复导入、重新导入曾安装的文件或本机时钟改变不会选错当前文件。

Runtime 的 `DataCatalog` 不依赖 Qt，提供目录查询、EOP 安装、finals2000A 原文件导入、偏好保存和按 `DataLock` 精确解析。每次加载核验清单、内容文件及时间依赖身份；当前只支持 EOP/内置时间这一组依赖。SQLite 使用 WAL、写事务和忙等待，串行化多个进程的发布；先验证临时副本、发布文件，再提交索引。启动时可恢复已发布而尚未写入数据库的有效快照，未发布临时目录不进入列表。Windows 发布目录时遇到临时访问拒绝或共享/锁冲突，最多额外重试 5 次，累计等待 620 ms；仍使用原子重命名，不退回部分复制。其他错误立即失败。这里不承诺断电时所有文件与数据库跨介质原子持久化。

多个场景共用相同文件，不各自复制数据。启动时按原身份导入附带快照及旧 `%LOCALAPPDATA%/OrbitForge/eop` 目录；迁移不改写已有项目文件。重复导入复用内容，已有损坏文件不会被新导入静默覆盖。损坏用户条目在窗口提示并排除加载；内置数据仍可从应用资源读取。旧内容目前作为内部缓存保留，没有用户历史管理功能；缓存清理尚未实现，项目正常打开不再依赖旧缓存。

## 全量下载与自动更新

入口为“数据 → 数据中心”，无需打开场景即可使用。左侧 EOP 默认展开，两个来源子项分别显示安装状态和覆盖截止，finals 下载中或检查异常时显示对应状态；UTC 条目保留有效截止。默认选中 EOP 父级，右侧显示有顺序编号和拖动手柄的来源列表，拖动后立即保存计算优先级；上移 / 下移按钮及 Alt+↑ / Alt+↓ 提供同样的排序操作。此页面说明实际完整覆盖优先于外推。

选中来源子项才显示该来源的详情与操作。左侧节点顺序固定，选中或展开节点不改变计算优先级；后台下载完成不改变所选节点，导入完成后展开 EOP 并定位到实际导入的来源。父级不展示某一份文件的安装徽标、下载按钮或覆盖日期，避免将来源状态误当作整个 EOP 类别的状态。

右侧显示所选来源的获取时间、覆盖起点、覆盖截止和最近检查结果。获取与检查时间使用本机时区，覆盖范围使用 UTC。历史覆盖结束仍可用于对应的历史场景。各来源的覆盖日期分别展示，避免把不连续或不同解算产品的时段误报为统一覆盖。

finals2000A 右侧提供完整下载 / 检查并更新、本地原文件导入、自动更新和外推设置；失败或中断后提供重试。C04 提供数据导入及独立外推设置，明确标注不联网检查；没有本地 C04 时仍可切换到该来源导入。UTC 标注随程序更新，不提供在线下载、EOP 优先级或外推。来源、实际文件路径、文件大小与哈希收在可展开区域，没有历史版本列表或应用到场景按钮。

自动下载与更新默认开启，也负责首次完整文件获取；已有用户关闭的偏好仍被尊重。启动后延迟 1.5 秒检查一次，此后仅在应用运行期间每分钟检查是否到期，不增加常驻服务。默认距上次尝试 24 小时，可在界面选择 6 小时、24 小时或 7 天，底层支持 1–168 小时。用户可关闭自动更新或随时手动下载。关闭窗口后下载继续，退出应用会中止；失败后的自动重试遵循相同间隔。

`DataUpdateStatus` 单独记录尚未检查、检查中、下载中、已更新、无新内容、失败、取消、中断，以及更换本地文件后待检查。`finals-update-record` 以带 schema 的结构化记录存入 SQLite settings，包含尝试时间、最后成功检查时间、被检查文件的 SHA-256 和结果。重启遇到未完成状态显示“上次下载未完成”；旧目录只有自由文本状态时不推断曾成功检查。失败、取消和 304 不改下载时间，失败/取消也不改最后成功检查时间。进度条使用服务器提供的总大小；总大小未知时显示活动进度与实际接收字节数。

成功安装后保存该来源的 ETag 和 Last-Modified。再次更新使用条件请求：收到 304 时不传输文件正文、不新建快照；收到 200 时校验完整文件后发布。200 返回相同字节时记录“无新内容”和实际下载时间。条件头只用于当前文件与上次验证文件的哈希一致、来源相同的情况，不因旧缓存中存在该文件而套用到另一份导入文件。导入不同内容后显示待检查；304 返回时再次检查当前文件未变。失败或仅收到响应头时不推进验证器。来源不支持条件请求时，完整获取后按 SHA-256 去重。这里没有承诺字节级增量传输，也不把不完整的 daily 文件拼接为历史版本；网络优化不改变完整文件身份及计算来源记录。

下载先进入 staging，使用 HTTPS、系统证书验证、不降级到 HTTP 的重定向、30 秒无活动超时、120 秒总时限和 16 MiB 大小上限。完成后校验传输结果、文件格式、完整逐日覆盖、数据数值及时间依赖，再发布快照。成功、失败或取消时清理本次下载临时文件；进程被强制终止时可能留下不参与加载的 staging 文件。不会把半成品标记为已安装，也不修改已有场景。Windows 便携包携带 Qt TLS 后端。

当前下载源为 [IERS finals2000A](https://datacenter.iers.org/data/9/finals2000A.all)。导入后的 ID 由全文件内容哈希构成，重复下载同一内容不会产生重复版本。原文件中的历史记录和不完整预测尾部全部保留；可计算范围取连续完整的 x/y、UT1、dX/dY 记录与时间 Provider 有效期的交集。导入时不对缺字段尾部补零或伪造覆盖；中间缺日、重复日、错误日期、部分缺损字段和非有限数拒绝安装。Bulletin A 的历史支持从 1972 年后的有效 UTC 起，不沿用 C04 的 1984 年限制。列定义以 [USNO 说明](https://maia.usno.navy.mil/ser7/readme.finals2000A)为准。

因此“完整文件已下载”与“任意未来日期可计算”是不同条件。界面显示实际可计算范围；UTC 超出内置时间数据有效期仍明确拒绝。未来时间数据更新必须加载并验证新的原文及规则，不能只延长旧表有效期。

## 覆盖不足与有限外推

覆盖不足时列出场景需要的时段、每种当前数据的原始范围及外推上限，并提供“打开数据中心”和“取消”。用户下载、导入或修改设置后重试；不静默缩短场景，不绕过 UTC 有效期。

每类 EOP 独立保存外推策略，默认关闭。启用时默认 3 天，可设 1–30 天；这里一天是 86400 个连续 TAI 秒，分别从原文件首、末样本起算。30 天是本软件的工程上限，不是精度承诺。外推算法 `endpoint-linear-tai-v1` 将端点状态按其一阶变化率线性延伸：UT1−TAI、x/y、dX/dY 分别计算，变化率保持端点值，与原 Hermite 插值在端点连续可导。使用 UT1−TAI 和连续 TAI 时间避免跨闰秒跳变，不将闰秒表本身外推。

IERS 文件内已有预测属于文件数据；越过完整有效样本范围后的软件线性估算明确标作外推。原始 first/last、文件 SHA-256 与插值版本不变，`EopDataInfo.extrapolation_days` 单独记录本次策略。超过上限 1 ns 或 UTC 有效期均拒绝。原文件覆盖充分时不会启用包装器，因此不必要的设置变化不改变计算身份。

场景标题标记“EOP 外推”，场景属性列出实际使用的外推时段、方法和上限；每个外推样本来源带方法、上限和距端点秒数，轨迹记录整个分析区间。项目 v4 保存策略，并纳入解释配置哈希。关闭外推后重新打开越界场景会提示覆盖不足；改变实际使用的外推上限须确认，不能从旧项目自动恢复已撤销的许可。一次计算保留启动时的策略，不受中途设置修改影响。

项目仍须通过结构、校验和及 DATA/LOCK 一致性校验。经用户允许更换数据后标记未保存，普通保存才更新磁盘文件。底层 `resolve_eop(lock)` 保留对原始数据的精确读取；桌面正常打开使用当前目录及策略，不依赖旧缓存。严格复现和导出项目依赖包留作独立能力。

## 开发顺序

1. **已完成：** 数据引用值、规范哈希、Scenario 绑定、项目 v4 持久化、旧文件升级和一致性验证。
2. **已完成：** SQLite 目录、文件去重、获取记录、按类型显示当前数据、旧目录迁移；打开或重算时检查数据变化并确认，哈希记录计算来源与外推策略。
3. **已完成：** finals2000A 全文件适配器、原文件导入、手动更新、HTTP 条件更新、取消与失败重试。C04 当前仍通过已有清单导入。
4. **部分完成：** 应用运行期间的自动检查/下载已实现；下一步实现按实例加载的时间 Provider，让 UTC 数据也能独立更新。
5. SPICE 和轨道目录适配器；按实际需求增加结果复现、项目依赖包和缓存清理。

各增量都保留离线使用能力。验收重点是身份可核验、一次计算的数据一致、更新可取消，以及任何下载或应用失败都保留已有可用文件和活动场景。

## Python 示例

```python
import orbitforge as of

catalog = of.DataCatalog('local/shared-data')
entry = catalog.install_eop('snapshot/manifest.json')
catalog.record_acquisition(entry.lock_sha256, of.DataAcquisition.imported)
# 也可直接安装完整原文件，自动推导可计算范围，不需要手工准备清单：
# entry = catalog.import_finals('finals2000A.all',
#     'https://datacenter.iers.org/data/9/finals2000A.all', '2026-10-10')
project = of.load_project('mission.orbitforge')
provider = catalog.load_eop(entry.lock_sha256)
project.earth_orientation = provider.data_info  # 记录本次实际使用的数据
print(catalog.snapshots[0].acquired_at_unix_seconds)
# 无界面调用者显式选择策略；不读取桌面设置：
limited = of.load_eop_snapshot(entry.manifest, extrapolation_days=3)
project.earth_orientation = limited.data_info
```

`ORBITFORGE_WITH_DATA_CATALOG` 默认关闭，图形桌面预设和标准 wheel 显式启用。关闭时 `data_catalog_available()` 返回 false，构造目录明确报告功能不可用；普通 headless 构建保持无 SQLite 依赖。
