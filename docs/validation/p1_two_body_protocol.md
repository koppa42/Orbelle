# 通用二体传播与桌面显示验证协议

本协议在实现和数值测量前固定首个通用传播器的边界与容限。当前步骤属于 P1/P2 目标中的轨道能力建设；P0 的图形呈现计时缺项仍需解决，不将它标记为已经通过。

## 模型与接口

- 优先复用已锁定的 CSPICE N0067 `prop2b_c`，采用 universal variables 从 Cartesian 初始状态传播；不自行重复编写通用 Kepler 求解器。该函数没有内核文件依赖，可统一使用 m、m/s、m³/s² 和秒。[NAIF 接口说明](https://naif.jpl.nasa.gov/pub/naif/toolkit_docs/C/cspice/prop2b_c.html)
- 首个公开入口接受地心 GCRF 初始状态及显式 μ。状态的历元使用现有 Epoch（TAI 纳秒）；模型的时间差和速度均对连续 TAI 秒定义，与 TT 的时间差相同，不调用 TAI→TDB 变换。这是理想二体模型，不是太阳系星历时间模型。
- 支持非径向的椭圆、抛物线、双曲线初始状态；初始状态不可变。拒绝非有限数、非正 μ、零位置/速度、径向退化运动及非 GCRF/地心状态。算法数值溢出或失败应明确报错，并且不污染后续 CSPICE 查询。
- 所有底层 CSPICE 调用共享现有全局互斥和错误处理约束。此计算不清空或切换星历内核上下文，不把无文件依赖误解为可绕过全局同步。
- Provider 实现位于 `providers/spice`，通过 Runtime 装配 Application Session。Core / Application 不引入 CSPICE 类型或库依赖；Python、SDK、桌面共用同一入口。关闭 CSPICE 的构建保留既有圆轨道案例，并对通用传播器入口明确报能力不可用。
- 当前入口采用明确的 Cartesian 状态，不隐式接受 J2 平均根数或 TLE 平均根数；根数转换、J2 和 SGP4 继续分步建设。

## 预先固定的数值检查

| 检查 | 范围和容限 |
| --- | --- |
| 初始历元 | 请求初始 Epoch 时逐分量返回原值，元信息一致 |
| 人工解析圆轨道/椭圆 | 米级构造算例，位置和速度各分量绝对误差 ≤1e-8 m、1e-8 m/s；计入请求历元纳秒量化 |
| 人工抛物线 | μ=6、初始 r=(3,0,0)、v=(0,2,0)；t=±4 s 的 Barker 解为 r=(0,±6,0)、v=(∓1,1,0)，相同 1e-8 容限 |
| 人工双曲线 | μ=1、初始 r=(1,0,0)、v=(0,2,0)，e=3；H=ln(2) 的解析位置/速度，计入 Epoch 量化，相同 1e-8 容限 |
| 地球轨道独立对照 | 同一 μ、GCRF 和初始状态，对照冻结版本 Orekit 的 KeplerianPropagator；典型 LEO/GEO/偏心/倾斜/逆行/双曲线，±1 日内位置各分量 ≤0.01 m、速度各分量 ≤1e-5 m/s |
| 守恒量 | 比能量变化相对初始 `max(μ/r, v²/2)` ≤5e-12；角动量向量变化相对初始模长 ≤5e-12 |
| 正反传播 | 典型地球椭圆、双曲线 ±1 日，重新以传播后的状态建立 Provider 再返回：位置各分量 ≤0.005 m，速度各分量 ≤5e-6 m/s |
| 并发和错误恢复 | 多线程请求同一/不同二体 Provider，与星历查询交错；结果与串行一致，错误后仍可查询；sanitizer 检查 |

独立参考不得由被测 CSPICE 实现生成；参考 JAR 延用已冻结的 Orekit 13.1.2 / Hipparchus 4.0.2 及 SHA-256。同一工厂的 C++ / Python 一致性属于绑定验证，不代替独立对照。误差容限描述模型实现一致性，不承诺真实轨道预测精度。

## 同步桌面显示

本轮同时接入倾斜、偏心的二体轨道显示，覆盖轨迹采样、时间播放/跳转以及两个视图对同一状态的显示。轨道状态来自 Application，ITRF 显示通过现有显式参考系转换得到，不在渲染模块另算轨道。

- 普通场景可编辑地心 GCRF Cartesian 初态、μ、初始历元，明确单位和 TAI 时间原点；按“应用”后在后台构建候选结果，支持取消，成功后才发布新版本。输入、数据覆盖或计算错误保留原场景。2026-10-09 根据用户后续反馈，将分析时段统一移至 Scenario 创建面板；卫星属性显示其继承的只读时段。
- 播放使用拥有数据的 ITRF 位置/速度三次 Hermite 显示缓存，不调用传播器或获取 CSPICE 锁；严格禁止外推。最多 10,001 个节点，用户可选 1–60 秒步长。发布前逐段在 1/4、1/2、3/4 处与直接计算核对，位置向量误差须 ≤1 m；记录实际最大值。这是离散检查，不声称严格的全区间误差上界。轨迹折线按节点绘制，其弦误差与标记插值误差分别对待；缓存只供显示，不作为后续 Access 输入。
- 轨迹各点使用各自历元转换，标为“地固空间轨迹”，不强制闭合。相机按三维位置和轨迹范围适配，两个视图保持独立。显示时段必须在 EOP 数据范围内；初始历元本身不受显示数据覆盖限制。
- 验证有效修改、无效修改后的原场景保留、取消、分析起止跳转、全部原生窗口关闭后的修改与重开；轨迹资源替换沿用稳定 CompileManager 屏障，编译失败尝试恢复旧轨迹。2026-10-09 工作流调整为修改后选中刚更新的对象，插入后选中新对象；保留其他对象的数据和外观。
- 新增 Scenario 流程检查：启动无场景时禁止插入、取消新建、创建空场景、关闭插入草稿、实际插入卫星、重复 ID 拒绝、多卫星独立编辑与外观、关闭属性不应用草稿。数值容限与冻结万星基准不因 UI 修改而改变。
- 保持已冻结的万星基准输入、目标分辨率和性能门槛；普通桌面新案例单独记录。
- 新案例检查非零 Z 分量、随时间变化的半径、正确的对象 ID / Epoch / frame，以及轨迹采样范围内的显示对应关系。
- 验证两窗口共享设备和场景、独立相机、时间变化、缩放及窗口重建；运行 Vulkan 验证层，检查错误/警告，保留截图及数值报告。
- 沿用既有错误路径：缺失显示资源或不可用 Vulkan 驱动应明确失败。性能探针继续独立执行，截图或数值一致不等同于帧时间与交互延迟达标。

新增公开接口须通过 Core-only 构建、启用 CSPICE 的 C++ 测试、安装后的 SDK 与独立 Python wheel 验证，并在 Windows / Linux 检查。首个步骤不声称完成 P1 的全部编辑、持久化、J2/SGP4 或 P2 Access。
