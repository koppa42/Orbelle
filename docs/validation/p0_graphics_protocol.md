# P0 图形集成验收协议

本轮先验证 Qt/VSG/vsgQt/Rocky 的集成与生命周期，再按已批准场景开展性能验收；单个窗口或少量对象的成功不能代替万颗卫星验收。

## 集成约束

- 保留 Core/Application、Python 与无界面 SDK 的独立构建。VSG/Rocky 类型仅进入渲染适配层和桌面装配层。
- Qt 6 Widgets 内嵌 vsgQt 原生窗口；两个视窗共享 VkDevice 和可共享场景/GPU 数据，相机及视窗状态独立。
- 地球显示使用 Rocky。地图显示数据显式指定、本地固定版本；不自动加载网络地图。
- 渲染地球固定系明确标记为 ITRF。固定圆轨道案例从 Application 取得 GCRF 结果，经 ERFA/IERS 显式旋转为显示快照；不得把 GCRF 坐标直接贴到地球固定坐标。
- 显示副本可使用 GPU 浮点格式，原始结果仍以双精度 SI 值保存，显示不回写计算结果。
- 创建、更新、视窗调整与销毁在 Qt GUI 线程调度。释放 GPU 或原生窗口前停止帧调度并等待相应 GPU 工作完成。
- 记录具体 VSG/vsgQt/Rocky/Qt/Vulkan 版本、源码散列、构建选项、设备与驱动；补丁纳入 overlay。

## 集成验证

1. 两个视窗都输出可观察的地球与卫星图像，报告实际像素尺寸及设备身份；导出本程序自身交换链图像用于检查，并独立记录实际 present 结果。若未取得桌面合成画面，不把交换链读回称为桌面截图。
2. 固定案例 6 个采样点与无界面入口相同；独立检查旋转后的快照数值与元数据，错误标签/历元明确拒绝。
3. 运行 Vulkan validation，创建、持续播放、Resize、Dock 浮动/停靠、关闭/重新创建视窗及退出过程不得出现验证错误。
4. 两视窗相机独立；检查共享的 VkDevice 和场景对象身份，不能仅凭相同类名声称共享资源。
5. 按 100%、150%、200% 缩放分别运行，记录逻辑尺寸、devicePixelRatio 和实际交换链尺寸。自动缩放测试不代替跨物理显示器移动测试，后者另行记录。
6. 冷启动、显卡/图形数据缺失、初始化失败和退出路径可定位，不能只有退出码 0 而没有实际呈现。

## 性能验收保留项

正式性能负载仍以 `benchmarks/scenarios/windows_10k_two_views.json` 和技术路线确认记录为准：10,000 颗动态卫星，两个各 1280×720 的实际渲染视窗；每视窗固定最多 100 条轨迹、200 个标签。实际轨迹细分、标签规则、地理数据/LOD、采样时长和重复次数须在测量前写入场景清单。

场景清单 schema 2 已固定这些参数：100 条各 121 顶点的轨迹、每视图 200 个 GPU 标签、无影像/DEM 的 WGS84 椭球、最大 LOD 5 和 pixelError 32；计划每次预热 10 秒、稳定播放 60 秒、重复 3 次，分别采集 100 次缓存跳转和选中响应。冻结场景的集成证据另见[万星预检](p0_graphics_10k.md)。[呈现计时](p0_graphics_timing.md)及[GPU 与进程资源度量](p0_graphics_resources.md)已接入短探针；实际输出时间反馈仍不完整，三轮正式测量尚未开始。预检保留标签重叠以维持固定提交量，并不证明 200 个标签同时清晰可读。

稳定播放每视窗 P95 ≤33.3 ms、P99 ≤50 ms；已缓存时间跳转 P95 ≤200 ms，点击选中反馈 P95 ≤100 ms。计时必须说明是 CPU 提交、GPU 执行还是实际呈现/响应时间，不能用 Qt 定时器间隔替代帧耗时。冷启动和未命中数据单列，记录 CPU/GPU、RAM/VRAM、驱动及有效采样数量。阈值未经用户确认不修改。

原始反馈和结束排空的最新证据见[呈现反馈与排空验证](p0_presentation_feedback.md)：尾部反馈已收齐，完成记录中的输出时间仍有不可用值，正式性能准入未通过。
